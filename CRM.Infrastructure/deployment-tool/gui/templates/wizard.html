Network Topology

                    
                

                

                    
Choose how containers communicate. This affects Docker network creation, firewall rules, and cloud VPC/subnet layout.


                    

                        

                            

                                

                                    
                                    
Single Network

                                    Simple
                                

                                
All containers (API, frontend, DB, providers) on one flat bridge network. Best for dev/small teams.

                                
    
                                    
  • All services can reach each other by container name
    • 
                                    
  • Minimal configuration
    • 
                                

                            

                        

                        

                            

                                

                                    
                                    
Segmented (Recommended)

                                    Production
                                

                                
Three isolated networks: core (API+Frontend), data (DB+Redis), components (providers). API bridges all three.

                                
    
                                    
  • DB never exposed to providers or frontend
    • 
                                    
  • Matches cloud VPC subnet best practices
    • 
                                

                            

                        

                        

                            

                                

                                    
                                    
DMZ + Internal

                                    High Security
                                

                                
Public-facing DMZ (Frontend + reverse proxy) and private internal network (API, DB, providers). Only the proxy bridges both.

                                
    
                                    
  • API & DB never directly reachable from outside
    • 
                                    
  • Ideal for cloud with public/private subnets
    • 
                                

                            

                        

                        

                            

                                

                                    
                                    
Host Networking

                                    Advanced
                                

                                
Containers bind directly to the host network stack. No Docker bridge overhead, but requires careful port management.

                                
    
                                    
  • Maximum performance, zero NAT overhead
    • 
                                    
  • Linux only — not supported on macOS/Windows Docker
    • 
                                

                            

                        

                    


                    
                    

                        
Inter-Network Communication Rules

                        

                            

                                
                                    
FromToAllowedPurpose

                                
                                
                                    
                                
                            

                        

                        

                            
                            
                        

                        

                            
                            
                        

                    


                    

                        
                        Single bridge network — all containers communicate freely. Suitable for development and small deployments.
